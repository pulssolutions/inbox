# Local development

Run the whole product on your machine with no AWS: the service against
in-memory fakes, the web app against the service.

## Two processes

```bash
# 1. API — in-memory fakes, seeded with a couple of messages, no AWS
cd aws/services/inbox && npm run dev            # http://localhost:3600

# 2. Web app
cd aws/web/inbox
echo 'VITE_API_BASE=http://localhost:3600' >> .env.local
yarn dev                                        # http://localhost:5173
```

Data lives in memory: restarting the API resets everything to the seed.

## Skip the login

The dev server reads the JWT payload without verifying its signature, so a
hand-made token works. Paste this into the browser console once and reload —
it seeds a superadmin session for the `acme` org the dev server uses:

```js
const orgs = { acme: { name: 'Acme Ltd', active: true, categories: '*',
  capabilities: { inbox:{read:true,write:true,send:true},
                  admins:{read:true,write:true,delete:true}, audit:{read:true} } } }
const b = o => btoa(String.fromCharCode(...new TextEncoder().encode(JSON.stringify(o))))
  .replace(/\+/g,'-').replace(/\//g,'_').replace(/=+$/,'')
const idToken = 'x.' + b({ organizationId:'acme', email:'demo@acme.example',
  name:'Demo Admin', orgs: JSON.stringify(orgs) }) + '.y'
localStorage.setItem('inbox:admin', JSON.stringify({
  user:{email:'demo@acme.example',name:'Demo Admin'}, idToken, accessToken:idToken,
  refreshToken:'none', expiresAt: Date.now()+31536000000, orgs, currentOrg:'acme' }))
localStorage.setItem('inbox:org','acme')
location.reload()
```

`localStorage.clear()` undoes it. Add `localStorage.setItem('inbox:theme','dark')`
before reloading to start in dark mode — the theme is read once at boot, so it
needs a reload rather than a hash navigation.

**This proves nothing about production security.** The deployed API sits behind
an API Gateway JWT authorizer that verifies signatures against Cognito; the same
forged token returns 401 there. Verified by trying it.

## Seeing states that need data

The audit log starts empty because entries are written by actions. Generate some:

```bash
TOK=$(node -e "
const orgs={acme:{name:'Acme Ltd',active:true,categories:'*',capabilities:{inbox:{read:true,write:true,send:true},admins:{read:true,write:true,delete:true},audit:{read:true}}}}
console.log('x.'+Buffer.from(JSON.stringify({organizationId:'acme',email:'demo@acme.example',name:'Demo',orgs:JSON.stringify(orgs)})).toString('base64url')+'.y')")
curl -s -X PATCH -H "Authorization: Bearer $TOK" -H 'content-type: application/json' \
  -d '{"assignee":"demo@acme.example"}' http://localhost:3600/admin/messages/seed-1
```

Or just act in the UI — archiving, assigning, replying and noting each write one.

## Brand artwork locally

`deploy.mjs` stages the profile's logo into `aws/web/inbox/public/brand/` at
deploy time, and that directory is gitignored. A local build therefore has no
artwork and falls back to the product's neutral mark. To see the real thing:

```bash
cp deployments/assets/<name>/logo.png      aws/web/inbox/public/brand/logo.png
cp deployments/assets/<name>/logo-dark.png aws/web/inbox/public/brand/logo-dark.png
printf 'VITE_BRAND_LOGO=/brand/logo.png\nVITE_BRAND_LOGO_DARK=/brand/logo-dark.png\n' \
  >> aws/web/inbox/.env.local
```

## Traps

**npm fails with E401.** A developer `~/.npmrc` pointing at AWS CodeArtifact
applies here too, and its token expires. Each package directory carries an
`.npmrc` pinning the public registry — every dependency here is public. Keep
those files.

**CI runs Node 24; your shell may not.** `.nvmrc` pins it, and mise reads that
via the `[settings]` block in `mise.toml`, but only if mise is active in your
shell. Verify against the pinned version before claiming green — `node --test`
changed behaviour in Node 22 and a directory argument now throws.

**Tests must not read the ambient environment.** Both suites pin what they read
(`LOCALE` in the service, the `VITE_*` vars in the web app) because
`.env.local` is generated by a deploy and gitignored: without pinning, the tests
pass only on a machine that has deployed. This has bitten three times.

**The browser tool cannot attach.** `chrome-devtools-mcp` keeps its own Chrome
profile and refuses to start a second instance against it:

```bash
pkill -f "chrome-devtools-mcp/chrome-profile"
rm -f ~/.cache/chrome-devtools-mcp/chrome-profile/Singleton*
```

That profile is the automation browser's, not your everyday Chrome.

## Checks

Everything CI runs, in order:

```bash
node --test test/*.test.mjs                       # profile expansion
cd aws/services/inbox
npm run lint && npm test && npm run test:integration && npm run package
(cd pretoken && npm test) && (cd presignup && npm test)
cd ../../web/inbox && yarn lint && yarn test
```

`pretoken` and `presignup` are separate packages — the service-level `npm test`
does not cover them.
